# Studio-owned Flow UI

This directory owns the Flow canvas, Runs, Inbox, Start Flow, Diagnostics and configuration UI. Studio reaches the Flow API through named Superverse gRPC operations. The Go backend reaches the selected Preview or Live Dex Server directly; Dex Web is not a runtime dependency.

`FlowApiProvider` (`lib/flow/FlowApiProvider.tsx`) gives each mounted resource its own Flow API client (`lib/api/transport/flow-api-client.ts`), bound to the resource's same-origin API prefix. A scope change disposes all requests and remounts its catalog and dialogs. Observed deployment/workspace identities are concurrency selectors. The BFF checks same-origin and a signed session-bound CSRF token on writes; Go authenticates the caller, authorizes the Project, and resolves target, definition and Worker identity on every operation. No browser role, permission selector, upstream address or health bypass is accepted.

Setup's checklist (`connections/`) renders the exact manifest returned by `POST /api/v2/connector-native-sessions`. OAuth setup, write-only credential fields, trigger configuration and application environment are native forms. `NativeConnectorUnit` handles the finite supported units of its `UNIT_SPEC` table. Provider data is requested only with command IDs the release manifest declares, through named Superverse gRPC operations behind the nonce-bound command endpoint. Imported provider projections preserve pagination, regional fallbacks, model capabilities, manual entry and list failure notices. Unsupported units display an explicit error; there is no iframe or arbitrary-JavaScript fallback. Application Preview content remains an intentional user-application iframe elsewhere in Studio.

Diagnostics retains the imported execution graph, Timeline, active state and channel messages, bounded resumable Stream view, Stop and Time Travel forms. Diagnostic Run IDs select engine history only. JSON payload bytes cross the generated transport without rounding FDG-defined integers.

`npm run check:pins` rejects reintroduced shared UI dependencies, verifies any remaining non-registry package pins and parses all Studio application/component/library sources to reject shared package imports, management frames, remote scripts, browser Worker/permission selectors and HTTP forwarding from management routes. Its only frame exception is the existing `PreviewPanel` application surface; the existing inline theme bootstrap is the only script exception.

| Capability                                      | Local owner                                                                           | Flow API boundary                                                                             |
| ----------------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |

| Execution diagnostics                           | `DiagnosticsView`, `RunDiagnosticsView`, `useRunRecord`, `ExecutionGraph`, `Timeline` | Original engine history/state; graphs reconstructed from events without applying a newer FDG  |
| Streams, channel inspection and removal         | `StreamPanel`, `LiveFlowState`, `SelectedEventPanel`                                  | Bounded resumable reads; explicit diagnostic mutations through named RPCs                     |
| Stop and Time Travel                            | `StopFlowDialog`, `TimeTravelDialog`                                                  | Diagnostic Run ID and selected operation; caller/target authorization remains backend-owned   |
| Connections and OAuth                           | `SetupRow`, `ConnectionPicker`, `ConnectorForm`, `NativeConnectorUnitHost`            | Native session + declared command IDs, write-only credentials, signed original callback scope |

Live credentials are shared across release drafts and builds; saving credentials affects the next Connector call. Ordinary configuration changes require a new build/deployment. Native Connector units preserve declared provider listing, pagination, search, manual entry and error behavior. An unsupported unit is an explicit error, with no remote code fallback.

## File map

| Directory      | Contents                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scope/`       | Studio's only entry: `FlowScope`, `LiveFlowScope` and `SessionFlowScope` bind the Flow UI to a Project-scoped Flow API base path, supply its navigation and show the catalog's notice; `LazyFlowViews.tsx` loads the views on demand; `FlowSurfaces.tsx` gates the Runs and Inbox surfaces; `SetupChecklistSurface.tsx` hosts Setup's checklist and `LiveIdentitiesSurface.tsx` the connections and channels a Live draft will run with.                                                                                                                                                                                              |
| `frame/`       | `FlowFrame`, the root of every Flow view with its canvas or page plane; its element defaults key on `data-flow-frame` in the base layer of `app/globals.css`. `FlowLink`, which links to a Flow target through `FlowNavigationProvider`; `flowTargetHref` in `lib/shared/studio-routes.ts` builds its Studio URL. `workspace-styles.ts` holds the class constants Runs, Inbox and Connections share: the list column, the case and its facts, and the form fields. `pane-bounds.ts` holds the presets and storage keys of the list column of Runs, Inbox and Connections, the run drawer, the Step panel and the selected event pane. |
| `canvas/`      | `FlowCanvas` and its chrome: `FlowCanvas` finds the definition and run, and `FlowGraphCanvas` draws a decoded Flow; `model/` decodes the definition and run overlay, `layout/` places the Scene, `render/` draws it with React Flow.                                                                                                                                                                                                                                                                                                                                                                                                  |
| `design/`      | An agent's Flow design: its expansion into the canvas's graph, its comparison with the current source, and `DesignFlowView`, which the Flow tab draws under its Design label.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `run/`         | Runs and Inbox: run list (of one Flow type, or merged across all of them) and search, folding to a rail with its icon; `detail/` holds the run drawer, the selected run's Display and Actions, liveness and copy; `step/` what a reader may do at the clicked Step (Inbox, Time travel, ask the agent, Fix on Preview); `start/` the Test run and Live run dialog and its typed input model.                                                                                                                                                                                                                                          |
| `map/`         | The Flow tab's project map: a card per valid Flow Type with its Steps and who acts, links where a subflow starts another Process, and change markers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `diagnostics/` | The Diagnostics page, Streams, Stop and Time Travel; `graph/` the execution graph, `timeline/` the Timeline and selected event, `event/` and `value/` render history event details.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `connector/`   | Connections and their setup steps and connection form; `manifest/` the manifest field controls and authorization methods; `native/` the native units, their picker options, the host that runs their commands and saves their values, and the provider projections in `native/model/`.                                                                                                                                                                                                                                                                                                                                                |

The Flow API documents and calls live in `lib/api/flow/`: the definition graph and run wire types, status and history readers, blob hydration, and one module per Flow API service (`flow-run.ts`, `flow-diagnostics.ts`, `connector.ts`, `application-environment.ts`), so no component builds a Flow API path. The client is in `lib/api/transport/flow-api-client.ts`; its provider, the navigation and the catalog in `lib/flow/` (`FlowApiProvider`, `FlowNavigationProvider`, `FlowCatalogProvider`, the exact definition-revision binding and enum labels); the resizable panes and their shared drag and keyboard gestures in `components/ui/pane/`.

Static source checks do not establish business acceptance. The real Native and full Local Kind journeys remain the execution evidence. Fixture mode supplies explicit local catalogs, native configuration and Publishing state for layout work; it does not invoke a model, Stripe, Gmail, GitHub or a real Flow execution.
